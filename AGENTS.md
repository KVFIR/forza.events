## Supabase Edge Functions

### JWT verification (`verify_jwt`)

- New functions default to **`verify_jwt = true`** unless configured otherwise.
- Activity-first functions (`token-exchange`, `save-event`, `browse-events`, `host-drafts`, etc.) use **`verify_jwt = false`** because auth is **`x-discord-access-token`** + `verifyDiscordToken()`, not Supabase user JWT.
- **`verifyDiscordToken`:** 30s per-isolate cache; Discord **429** throws `DiscordRateLimitError` (callers return 503), not `null`/401.
- **Always deploy** public/browse/draft functions with:
  ```bash
  npx supabase functions deploy browse-events host-drafts --no-verify-jwt
  ```
  or `npm run deploy:functions` (script uses `--no-verify-jwt` for every function).
- `supabase/config.toml` must list `[functions.browse-events]` and `[functions.host-drafts]` with `verify_jwt = false`. Config alone is not enough if a one-off deploy omitted `--no-verify-jwt`.

### Gateway 401 vs app 401

| Symptom | Likely cause |
|--------|----------------|
| `UNAUTHORIZED_NO_AUTH_HEADER` / missing authorization | Gateway: no `Authorization` and/or `verify_jwt` still true |
| `{"error":"Unauthorized"}` from function body | App: invalid/expired Discord token on `host-drafts` / `host_drafts` |

- With `verify_jwt = false`, gateway accepts **`apikey`** alone (verified via curl).
- With `verify_jwt = true`, gateway expects **`Authorization: Bearer <SUPABASE_ANON_KEY>`** (anon key is a valid JWT).

## Discord Activity proxy

- URL mapping: prefix `/supabase` → `{project-ref}.supabase.co`. Client keeps real `VITE_SUPABASE_URL`; `patchUrlMappings` rewrites fetches.
- **Cover images in Activity:** Discord CSP `img-src` allows `'self'` and Discord CDNs only — not `*.supabase.co`. `coverDisplayUrl()` rewrites Storage/render URLs to `/supabase/...` for `<img>` (fetch proxy does not apply to `img src`).
- **Publish target lists:** `list-guilds` intersects user guilds with **one** cached `GET /users/@me/guilds` (bot token), not N× `GET /guilds/{id}`. `list-channels` fetches user guilds once; channel permissions include **category** overwrites. Load channels only after guild list finishes (client).
- Discord’s proxy often **drops `apikey` and `Authorization`** on forwarded requests (documented for PostgREST; applies to `/functions/v1` too).
- **Fix:** In the Activity iframe, route Edge `fetch` through **`createSupabaseFetch(anonKey)`** (`src/lib/supabaseEnv.ts`) so headers are re-applied on every request — same pattern as the Supabase JS client.
- Plain `fetch()` to `functions/v1/*` from `api.ts` **without** that wrapper will 401 in Discord even if localhost works.
- **`getSupabase()`** (PostgREST: results, cars, realtime) also **`await ensureDiscordSupabaseProxy()`** before use in the Activity iframe — otherwise cold-start Event Detail can race `patchUrlMappings` and show `fetch_failed` on `event_results`.
- **Event Detail results:** prefer Edge-embedded `publishedResults` from detail select (`loadResultRowsForPublishedEvent` skips PostgREST unless `forceNetwork`); Live/in-progress empty or failed reads must not set `loadFailed` — only `completed` shows retry UI.
- **Client `@edge` imports:** `src/` code that shares Edge helpers imports `@edge/*` → `supabase/functions/_shared` (`vite.config.ts` `resolve.alias`, `tsconfig.app.json` paths; vitest already uses the same alias). **Vite dev:** the `/supabase` proxy must `bypass` `/supabase/functions/_shared/*` so Vite serves repo files — otherwise a relative import resolves to the Supabase API (401) and breaks lazy route chunks (e.g. Event Detail via `groupRoster.ts` → `planGroupBalance`).

## Client API (`src/lib/api.ts`)

- All `invoke()` calls should set **`apikey`** and **`Authorization: Bearer <anon>`**.
- When `isDiscordActivityFrame()`, use **`createSupabaseFetch(anonKey)`** as the fetch implementation for `invoke()`.
- Pass Discord user token only in **`x-discord-access-token`**, never replace the Supabase Bearer with the Discord token. Edge reads it via `discordAccessTokenFrom` / `requireDiscordUser` / `optionalDiscordUser` (`discordRequestAuth.ts`) — never fall back to `Authorization` (that header is the anon JWT; verifying it as Discord wastes quota and can surface as `browse-events` `INTERNAL` when Discord returns 429). `DiscordRateLimitError` maps to 503 `TOO_MANY_REQUESTS` in `requireDiscordUser` / `optionalDiscordUser` and `internalErrorResponse`.

## Auth / session

- `isSignedIn` = `user.discordId` **and** `getDiscordAccessToken()`.
- **Browser OAuth session** (`discordAuth.ts`): access token + optional `refresh_token` / `expires_at` + user in **`localStorage`** (migrates legacy `sessionStorage` on read) so sign-in survives new tabs from Discord embed links; Activity iframe auth stays in-memory + same keys on the Activity origin only.
- Saving drafts can work (token in module) while **My Events** stays empty if React `user` is still `GUEST_USER` — e.g. OAuth callback called `setDiscordSession` but not **`refreshUser`**.
- `AuthCallback` should `refreshUser(result.user)` after token exchange; use **`exchangeTokenOnce()`** so React StrictMode does not double-exchange the OAuth `code`.
- **Token refresh:** Discord access tokens last ~7 days. `token-exchange` accepts `{refresh_token}` (`grant_type=refresh_token`) and returns a new access + rotated refresh + `expires_in`. Browser init refreshes when within 1h of expiry (`discordSessionRefresh.ts`); `api.ts` `invoke()` on Edge **401** tries one forced refresh then retries; only clears session + `SESSION_EXPIRED_EVENT` when refresh is missing/rejected (not on transport blips). Sessions saved before this ship need **one** re-login to obtain a refresh token.
- **Browser sign-out:** standalone browser (`isStandaloneBrowser()`) shows **Sign out only** in `AuthStatusIndicator` when signed in (no paired Online/Local status pill — either/or). `signOutBrowser` clears session, `saveAuthReturnTo` current path, then `navigate('/sign-in', {replace: true})`; Activity auth path unchanged.
- Optional: sync `loadDiscordSession()` into context on mount if session exists but state is stale.

## Security (Edge + Storage + RLS)

- **Mutations** use Edge Functions + `verifyDiscordToken()`; Postgres RLS is read-only for anon on sensitive tables.
- **Cover uploads:** `upload-cover` only (host + `event_id`). Optional body `guild_id` must match the event when both are set. Storage path is `{guildId|draft}/{eventId}/cover.*` from the event row only (not client-supplied). Baseline schema drops anon storage write policies on `event-covers`.
- **Publish target:** `publish-event` and `validate-channel` call `validatePublishChannelTarget`; user must be guild member with Manage Server (`guildAccess.ts`).
- **OAuth:** `token-exchange` whitelists `redirect_uri` via `oauthRedirect.ts` (+ optional `DISCORD_REDIRECT_URI_ALLOWLIST`).

Catalog is per-game (`cars.game` = `fh5` | `fh6`; migration `029`). Refresh prod: `npm run data:fh5:scrape` / `data:fh6:scrape` then `npm run seed:cars` (upsert via `029` unique index; never `DELETE FROM cars` / `event_cars`). - **Results:** `submit-results` requires `discord_id` in `event_participants`.
- After publish, `assertTargetNotLocked` blocks changing `guild_id`, `channel_id`, and `game` on save.
- **Anon PostgREST reads (baseline RLS + `003_security_publish_results`):** `users` / `event_participants` / `event_results` / `event_cars` only for non-draft events (or tied rows) — not full-table scraping.

## Learned Workspace Facts

- Seeding test events for publish flow: use `status = draft` — `status = open` without `discord_message_id` blocks `publish-event` (`NOT_DRAFT`) while UI still treats the row as a draft.
- PostgreSQL RPC pitfalls: `coalesce(smallint_col, 1)` infers `integer` → `42883` on `smallint` args (migrations `011`–`013` cast explicitly); duplicate `change_event_group_leader` `integer`+`smallint` overloads → PostgREST `PGRST203` when Edge passes JSON number for `p_group_index` → unmapped 500 — migration `025` drops integer overload. `responseForRpcError` (`rpcErrors.ts`) maps `RAISE EXCEPTION` codes, `PGRST203` → `BAD_REQUEST`, `23505` on `ep_one_convoy_leader` → `LEADER_ALREADY_CONVOY_LEADER`, `23503` missing `users` FK → `CONVOY_LEADER_HANDLE_REQUIRED`; unmapped still → `INTERNAL` (`event-participation`, `change-group-leader`, etc.).
- **My Events catalog:** `usePublishedEventsLiveUpdates` silent-refetches browse when the signed-in viewer's `event_participants` row changes (host assign, waitlist, promote) — count-only `events` patches are not enough for `userIsParticipating`.
- **Link preview Worker:** export `resolveDefaultOgImage` from `shared/sitePageMeta.mjs` (Worker fails to boot otherwise); `isStaticAssetPath()` must always proxy `/og/*`, `/covers/*`, `/assets/*`, `/logo/*` to Railway — crawlers fetch `og:image` with bot UA. Keep `shared/sitePageMeta.mjs` ↔ `src/lib/sitePageMeta.ts` in sync (`tests/sitePageMeta.test.ts`).
- `events.timezone_hint` is the DB column (not `timezone`); Edge `select` on `events` must use `timezone_hint` — wrong column yields empty row and `EVENT_NOT_FOUND` on join.
- Remote migration history can list timestamp versions (`015`/`016`, or `025` as `20260714133038`) while repo uses numbered files — `migration repair --status reverted <timestamp>` then `--status applied <nnn>` before `db push`; prefer `supabase db push` over MCP `apply_migration` to avoid orphan timestamps.
- **Guild catalog:** `buildGuildCatalogUpsert` omits null `icon_url` (don't wipe cached icons); `settings.invite_url` cached on publish from channel invite; browse/detail load via `eventListSelect` join on `discord_guilds`; Event Detail roster ELO is nested `player_ratings` on `EVENT_DETAIL_SELECT` only (not the browse list) — **deploy functions** when `eventListSelect` changes.
- **PublishTargetPicker** guild-name sync must not clear `channel_id` or `isRanked` when `guild_id` is unchanged (`onGuildChange` only resets those on a real guild change) — name-sync with `ratingEnabled === false` was wiping Ranked on published edit.
- **Browse after start:** keep started/`live` in the public feed; successfully `completed` also stay (below active); within `completed`, `sortEvents` reverses only `event_date` (newest past races first); `created` / `fill` keep the same order as active. Exclude `cancelled`/`archived`. Do not reintroduce `starts_at > now` or registration-open gating. Discord LIVE embed keeps `open_event` **enabled** (`View in FORZA.EVENTS`) — registration-closed copy must not disable the button.
- **Event Detail results path:** Activity cold-start `fetch_failed` on `event_results` was often a second PostgREST before `patchUrlMappings`; `getSupabase()` must await `ensureDiscordSupabaseProxy`, and when Edge already embedded `publishedResults` skip that second request unless `forceNetwork`.
- Match API auth failures via `ApiRequestError` `code`/`status` (e.g. `UNAUTHORIZED` / 401), never i18n `error.message` — EN/RU copy broke `/unauthorized/i` in `fetchHostDraftEvents` and forced a useless `browse-events?host_drafts` fallback (double analytics noise).
- Profile **Participations** count includes the host when they held an active roster seat (incl. convoy leader); waitlist excluded; My Events → Joined includes the host when they have a roster row.
